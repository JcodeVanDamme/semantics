*** Software Architecture ***********************************************
- Bottom-to-top

-> Triple-File
- Persisted Triples
- serialization using N-TRIPLE / JSON
- Maybe; Split into two; Schema-File(RDFS) / Data-File(RDF)

-> Persistence-Layer
- Parse Triple-File
- Perform writes / deletes upon CREATE / DELETE or during Shutdown according to Log

-> Maybe; Log-Module
- Log CREATES / UPDATES / DELETES

-> Triple-Store
- Resides in Memory
- Holds Triples, indexed via SPO, OPS, POS
- Exposes Methods to add / delete / query Indices for a given Triple
- Upon add / delete; immediately update in-memory-Store to reflect changes

-> Inference-Module
- Applies RDFS-Rules (subClass / subProperty / domain / range)
- Expands Triple Store via inferred Triples
- (Some Form of, for each given Subject / Property) iterate over all related Triples, generate acccording Indices)

*** Inference-Strategy ***

--- Eager Option ---

- Perform Inference upon System start, iterating ovrer all Base-Triples generating all inferred Triples
- Perform additional Inference upon read / delete
-- Lazy / Simple Option (reused Startup-Logic) clear all Indicies, re-run complete Inference (Starting Point ?)
-- Cleaner / More efficient Option -> Only infer needed Indices

- PLUS
- Easy to implement
- Fast Reads (All Triples present in Memory)

- MINUS
- Prolonged Writes
- Prolonged System Start
- Memory-Inefficient (Large Datasets)

--- Lazy Option ---

- Perform Inference upon each Query Execution (Read, Write, Delete)
-
- PLUS
- Faster Writes / deletes
- + Memory-Efficient
- Faster System-Start

- MINUS
- Harder to implement
- Prolonged Reads
